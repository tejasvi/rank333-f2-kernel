## Build

- **KMod:**
  ```
  KMOD_LEAN_PATH=<frozen port build>:<library roots> KMOD_PLAIN=1 lean/kmod/build.sh KMod.Vocab KMod.Units KMod.Audit KMod.Comb
  ```
  For the tests, drop `KMOD_PLAIN=1` and pass `KModT.*`. `AUDIT.md` gives the expected result of each negative control.
- **HCapK and KCH:**
  ```
  LIB_PATH=<frozen port build>:<library roots> lean/hcapk/build_hcapk.sh <frozen port root> <out>
  ```
  This derives the 183 HCapK sources from the frozen port's sources and builds them, then the 45 KCH tables.

## Regenerate

- **Class packages (16,566 `kc_*`).** Run `emitpkg.sh <args...> OUT --threads 4` from the E1G emitter tools tree v7.1
  (tarball sha256 `f0718c2d3fffa48b7b5625ce8070624a8248d6d88f4eb4ba8194f39b9538bd09`). Assemble the tree with
  `generators/e1g/sh/mktools.sh v7.1 OUT`; its class contexts and the giants' `ip/subh*`, `ip/subtoph*` files are
  `inputs/e1g/ip_classes.tar.zst`. The `args` come from the package's line in `inputs/classes/kc_packages_*.jsonl.zst`. Build the emitted `manifest.jsonl` in dependency order with the pipeline's
  scheduler, against the closure of the final build.
- **Class aggregations (21 `kcagg_h<c>`).** Run `generators/classes/kcagg_vN/kcagg.sh <c> OUT DEPS` with the version the
  class used (v3 for 454 and 485, v2 for the other 19). `DEPS/<id>/DONE` and `DEPS/<id>/kext.txt` are each class package's
  emitter records, and the package roots' public `.olean` files must be in the store.
- **Cut lists.** `generators/classes/tools/kccut.py A.jsonl 5400 --no-giants` and
  `kccut.py B.jsonl 5400 --giants-only --id0=4332` reproduce the shipped lists byte for byte from the shipped
  `rootjobs.tsv` and giants. A1 and A2 split list A by class.
- **Emitter inputs and KCH tables of the 45 giants.** `generators/classes/tools/mkkch.py` writes them from `giants.tar.zst`.
  Its `ip/subh*` and `ip/subtoph*` outputs are byte-identical to those in tools tree v7.1 and in
  `inputs/e1g/ip_classes.tar.zst`.

## Determinism

The class packages, the class aggregations and the HCapK modules regenerate byte-identically. The emitter output depends
only on the tools tree and the spec line. The Lean outputs depend only on the source, the closure and the toolchain.

Checked cases:
- **Class package.** `kc_02356` (class 454, 3 modules) was re-emitted from its spec line with tools v7.1 and built against
  the final build's closure. Its root module `KC.h454_3234_3256_A` has `.olean`, `.olean.server` and `.ilean` identical to
  production (`.olean` sha256 `05b050697a5fa4ca1a1eadaae08b66ce82d9ab626f0a0ed309c50ce4932076e7`).
- **Job module.** `KC.h487h461_1594_1595_s1594_s50_L2` (of `kc_12152`) was rebuilt from its emitted sources. `.olean`,
  `.olean.server`, `.ilean` and `.ir` are identical to production.
- **Class modules.**
  - `KC.h458_Class` (v2) was regenerated by `mkclass_root.py` from the class's emitter records and rebuilt; its `.olean` is
    identical to production.
  - `KC.h485_Class` (v3) rebuilt with the production statement hashes (`jobs` 3577596154, `classLB` 68157045).
- **HCapK.** `HCapK.C454` and `HCapK.OK_h456_Base`, rebuilt from `derive_hcapk.py` output, have `.olean`,
  `.olean.private`, `.olean.server`, `.ilean` and `.ir` identical to the hashes in `OLEANS.sha256`.

## Notes

- **Built-in module docs.** These sources keep their module docs exactly as built, so that they rebuild to the listed
  hashes:
  - the KCH table docs name the giants' directory (`leaf2/kc/giants`);
  - the class modules' docs, emitted by `mkclass_root.py`, name the generator's path (`leaf2/kc/py/mkclass_root.py`);
  - the KMod library docs refer to section 7a of the KMod design plan, which is summarised in `lean/kmod/AUDIT.md`.
- **Not in the final import closure.** KMod (imported with `meta import`) and the KCH tables are needed to build the
  packages but are not in the import closure of `R22K.Final`. The 183 HCapK modules are in it; their `HCap` counterparts
  are not.
